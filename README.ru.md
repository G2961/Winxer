# Winxer

**[English](README.md)** | **[Русский](README.ru.md)**

Системный аудиопроцессор для Windows в стиле Metro (Windows 8): эквализация и обработка любого звука системы через цепочку VST3-плагинов. Пропусти музыку, игры или браузер через свои плагины – как мастеринг-стойка для всей системы.

Виртуальные кабели не нужны: установил прогу, нажал пуск – готово.

## Возможности

- **Захват системного звука** – process loopback Windows: Winxer забирает системный микс напрямую, исключая собственный вывод, поэтому нет петли фидбэка и не нужен VB-Cable
- **Хостинг VST3** – нативные редакторы в отдельных окнах, настройки живут, пока открыто приложение
- **Свои папки сканирования** – плагины не обязаны лежать в Program Files; поиск рекурсивный, до 4 уровней вложенности
- **Пресеты цепочек** – сохраняй и загружай целые наборы плагинов
- **Metro-интерфейс** – плитки, pivot-вкладки, живой отклик: прогиб под курсор, плавное сжатие у краёв, изменение размера плиток (ПКМ)

## Как это работает

```
системный микс (устройство по умолчанию) → Winxer (цепочка VST3) → ваши наушники/динамики
```

Winxer держит аудиограф: захватывает системный звук устройства вывода по умолчанию через process loopback (собственный рендер в захват не попадает, поэтому вывод может играть на то же устройство), обрабатывает блоки по 512 сэмплов через цепочку плагинов и пишет в устройство вывода. Пока приложение запущено и включён «пуск» – звук идёт через цепочку.

## Установка для разработки

Требования: Rust (stable, MSVC), Node.js.

```bash
npm install

# запуск
npm run tauri dev
```

## Использование

1. Выбери устройство для фильтрации на главной плитке (захват всегда идёт с устройства вывода по умолчанию Windows)
2. Собери цепочку на вкладке «плагины» – клик по плитке добавляет в цепочку
3. Жми «пуск» – звук идёт через плагины
4. «Окно» у выбранного плагина открывает его редактор; ПКМ по плитке – изменение размера

## Архитектура

- `src/` – фронтенд (Tauri WebView): Metro-плитки, цепочка, пресеты
- `src-tauri/src/audio.rs` – аудиодвижок: process loopback → цепочка → рендер
- `src-tauri/src/vst3support.rs` – хостинг VST3 через крейт vst3-host: загрузка, обработка, окна редакторов; весь control-plane плагинов живёт в постоянном STA host-потоке
- `src-tauri/src/vst.rs` – сканирование плагинов: стандартные и свои папки
- `src-tauri/src/bin/winxer-selftest.rs` – бесхвостовый тест жизненного цикла плагина (загрузка, DSP, кручение параметра, открытие/закрытие/переоткрытие окна)

## Известные ограничения

- Захват всегда идёт с **устройства вывода по умолчанию** Windows – чтобы фильтровать конкретное устройство, сделай его дефолтным в Windows
- Плагины-инструменты (SWAM, Serum и подобные) генерируют свой звук вместо пропускания входа – они глушат цепочку и бесполезны для обработки системного звука
- Формат запросов хоста у VST3 минимален – редкие плагины могут не открываться
- Латентность ~20–40 мс – норма для схемы loopback
